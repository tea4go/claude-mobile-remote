## E3 实施步骤

1. **专项设计与契约**：明确触发事件（至少权限审核/待回答事项）、通知收件人及会话定位、撤销/过期、重复事件处理和固定文案。WhaleTerm 到 edo 使用独立 HTTPS 通知接口；只传路由所需的不透明标识、事件类别及幂等 ID，不传 Pair Token、会话正文、工具参数、文件路径或 Claude 上下文。明确 edo 的存储期限、鉴权、限流和失败处理。该接口不是手机会话协议，也不承载命令或实时消息。
2. **edo 接收与转发**：部署认证后的通知接口，保管极光等第三方服务密钥；验证来源和请求、去重并有界处理失败，调用平台推送 API。WhaleTerm 已有线上自动升级证据证明其可向 edo 发起 HTTPS 请求，无须将这项连通性重新列为待核实门禁；通知专用接口仍须独立端到端测试。
3. **WhaleTerm 事件出口**：从已有宿主事件中产生通知，异步发送到 edo；发送失败不能阻塞 Claude、审批或 PC/手机输入队列。只记录固定结果类别和可关联的非秘密 ID，不记录推送凭证或正文。
4. **手机接收**：iOS 恢复已暂停的远程推送 SDK、Push capability、APNs 签名和设备注册；Android、Harmony 按各自平台完成等价接收与通知点击定位。沿用现有安全配对及本地 Session 定位语义；手机点击通知后按与 PC 网络互通的前提进入会话，不把异常网络恢复列入 E3。
5. **验证与交付**：验证审批等事件从 WhaleTerm 经 edo、第三方平台到后台/退出的手机；验证多 Session/多设备路由、重复/撤销/过期、凭证与正文不泄漏、发送失败不影响当前 Turn，并按 iOS、Android、Harmony 分别记录设备结果。通知送达与点击进入是不同验收项；不以本地通知或模拟器结果代替离线送达。

## 取消与保留的边界

- 取消可信公网 Relay、CLI 到云端的 WebSocket 隧道和依赖它的任意公网实时控制；不以 HTTP 包装会话流量绕过 WebSocket 审核。
- 实时会话仍使用手机与 PC 可互通的 LAN/VPN WebSocket；手机可通过多个本地配对记录切换多 PC/Session，不建设云端 Session 中心。
- D97 的 edo 审核模拟服务及公网 WSS 400 保留为历史部署结果；D98 已用 App 内离线演示替代其当前送审前置任务。E3 的 edo HTTPS 通知接口是另一项服务，不复用受阻的 WebSocket 路径。
- 在线本地通知继续保留，E3 只负责 App 后台/退出后的远程系统通知。
