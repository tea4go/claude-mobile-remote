# Harmony 点击响应排查与修复

用户确认仅修复 Harmony，保持协议、推送、iOS/Android 不变，不执行 Git 写操作。

## 证据与限制

- 华为上架自检针对 1.0.1 报告“点击响应时延严重”。用户后续补充 HarmonyOS 6.1 / Pura 80 Pro+、319.0ms、目标250.0ms，视频涉及 demo 操作及扫码；尚无逐次点击对应的 trace，不能宣称已定位云端唯一根因。
- 1.0.2 仅调整版本，与受检版功能相同。基线 Harmony 53 测试及 16 文件逻辑检查通过，不能证明 UI 性能达标。
- 已确认同步文件读写/刷盘在主线程运行；消息区在 Scroll/Column 中通过 ForEach 一次性创建全部消息；部分异步操作缺少可见进行状态。
- 本机有 API 24 官方 SDK/hdc；提升权限启动设备服务后 `hdc list targets` 为 `[Empty]`，当前无可采集的真机。

## 修复顺序

1. 原生存储改用 SDK Promise 文件接口，保留串行队列、HUKS 加密、私有权限、原子替换、缓存限额；附件读取/日志导出也使用异步文件接口。
2. 消息区使用 List/LazyForEach 只创建可见项；保留流式文本/状态更新和工具结果标题，避免附件 base64 参与渲染键。
3. 演示入口、扫码、连接和缓存清理提供即时状态和重复操作保护；演示组件创建/扫码原生跳转放在反馈帧之后，带页面退出及生命周期校验；非链接文本不注册空点击回调。
4. 补充存储异步行为/故障原子性、消息数据源更新测试；运行 Harmony 全量测试、SDK Release 构建和 diff 检查。
5. 提供可重复的 hdc/SmartPerf 命令行采集入口与说明；未连接设备时明确失败，不伪造时延。交付结果需要用户在真机/云测试复测，尤其是原云端失败路径。

## 验收

- 本机验证：存储安全及队列回归通过；流式/审批/退出逻辑通过；ArkUI/ArkTS Release 构建通过。
- 设备验证：扫码入口、连接反馈、演示进入/发送/审批/退出、消息滚动/抽屉、设置/清缓存/调试开关；冷暖状态和长消息分别采集，本次云端验收目标 <=250ms（报告319ms），通用体验优化可另按100ms观察，保留超标结果与 trace 继续定位。
- 不以构建通过、Node 耗时或主观体验替代系统触摸至首帧上屏时延。
