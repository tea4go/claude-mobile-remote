# B1 消息与移动 UI 实施计划

> **执行方式：** 按 Task 顺序逐项实施，每个 Task 内先写测试确认 RED 再实现 GREEN。步骤使用 `- [ ]` 复选框跟踪进度。Git 写操作需用户单独授权。

**Goal:** 在不改变现有通信协议和 Pair Token 存储边界的前提下，为 Mobile Web 增加页面内存 Session 列表、列表/详情切换、Markdown/代码块展示和更完整的状态提示。

**Architecture:** 保留现有 `ProtocolClient`、协议类型和单 Session reducer；新增轻量内存 `SessionStore` 管理配对记录，App 使用 `list/detail` 视图状态控制导航，并保证只有当前详情 Session 持有 WebSocket。Thinking/Tool 只实现只读占位，不接入真实结构化数据；真实结构化协议留给 B2。

**Tech Stack:** React 19、TypeScript、antd-mobile 5、Vite、Vitest、Testing Library；Markdown 候选使用 `react-markdown`、`remark-gfm` 和安全过滤配置，HarmonyOS NEXT 只复用展示语义与数据边界，不复用 React 组件。

---

## 文件与边界

- `apps/mobile/src/session/store.ts`：页面生命周期内的配对记录纯函数与内存 Store，不写浏览器持久化存储。
- `apps/mobile/src/session/store.test.ts`：记录新增、同 Session 更新、删除和状态更新测试。
- `apps/mobile/src/components/SessionList.tsx`、`SessionList.test.tsx`：列表卡片、新增入口、空态、删除和进入详情。
- `apps/mobile/src/components/SessionDetail.tsx`、`SessionDetail.test.tsx`：详情页状态栏、返回按钮、消息流和输入区域组合。
- `apps/mobile/src/components/MessageMarkdown.tsx`、`MessageMarkdown.test.tsx`：安全 Markdown/代码块渲染；不接入 Thinking/Tool 真实数据。
- `apps/mobile/src/components/StructuredBlockPlaceholder.tsx`、测试：Thinking/Tool 只读占位，不伪造结构化内容。
- `apps/mobile/src/App.tsx`、`App.test.tsx`：列表/详情编排、当前连接生命周期和 Fragment 边界。
- `apps/mobile/src/components/MessageFeed.tsx`、测试：接入 Markdown 渲染并保留现有来源、流式和错误语义。
- `apps/mobile/package.json`、`package-lock.json`：仅在依赖门通过后增加 Markdown 相关依赖；不增加第二套 UI 组件库。
- `docs/specs/2026-08-26-B1-mobile-ui-design.md`、`HANDOFF.md`：实施完成后记录实际范围、依赖结论和验证结果。

不修改 Go、协议 envelope、snapshot/event 字段、Pairing payload、Session Controller、Channel、Transport 或 `DECISIONS.md`。B2 再单独设计 Thinking/Tool 结构化事件、审批、AskUserQuestion 和取消。

## 依赖与跨端门禁结论

- antd-mobile 仍是唯一 UI 组件库；不引入第二套移动 UI 组件库。
- Markdown 第三方依赖只服务 React Web/Capacitor；HarmonyOS NEXT 实现同一受限语法和安全语义，不复用 npm 组件。
- 任何 C1 原生插件必须另行提供 iOS、Android、HarmonyOS NEXT 的能力矩阵；缺少等价能力时使用平台官方 API或降级，不把平台差异写入 B1 协议。
- B1 不修改 `DomainEvent`、`SessionSnapshot`、`PendingAction` 或任何版本 1 wire 字段；Thinking/Tool 结构化协议在 B2 单独设计并重新核对三端。
