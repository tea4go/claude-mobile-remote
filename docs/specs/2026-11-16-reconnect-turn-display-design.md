# 断线重连后的最近一轮有序展示（草案）

状态：用户已确认（D125）。针对 11-16 测试问题 2；不是全量历史或任意多轮离线补偿。

## 问题

现有 EventStream 将最近一轮所有 text_delta 拼接到 snapshot.turn.message，内容块不进入快照。客户端重连时只能看到合并文本，且既有步骤与文本之间的顺序会丢失。手机不可能从合并文本推算真实分段或缺失的工具调用。

## 建议方案

- 宿主按事件顺序维护最近一轮的有界展示片段：相邻文本合并，Thinking、tool_use 和 tool_result 使用现有受限展示字段；仅内存保存，不读 JSONL、不创建额外 SDK Client。开始新轮时替换上一轮。保留完整的当前权限事项和现有 turn.message 兼容投影。
- 协议增加版本化快照字段，携带有序片段、明确的截断标志，以及与快照相同的 seq 边界。最多 512 个片段、序列化数据 512 KiB；超限保留最近片段、明确提示早期过程未同步，按 UTF-8 和单片段大小安全裁剪。工具结果仍遵守既有限额，禁止凭证、图片数据及执行缓存路径。具体实现须测试最大转义后的传输体积与 outbox 限额。
- 新客户端收到带片段的快照时，以该轮权威片段替换同一轮旧展示并避免重复，保留其他轮次；有截断时提示。没有新字段的旧宿主使用现有快照降级，无法声称恢复顺序。建立有序投影后产生的事件才能被恢复，不能追溯升级之前未保存的步骤。
- EventStream 的快照与订阅在同一锁及 seq 边界内取得；Standalone Controller 采用其串行事件循环保持相同语义。旧协议版本不发送新增字段；新旧版本互通，不能使 Harmony 的严格解码失败。
- iOS/Android 共用 React 类型和展示实现，Harmony 独立实现相同字段、限额、去重和截断提示。先实现及验证 iOS，用户验收后再同步 Android 和 Harmony；三端协议能力协商与旧版本降级须在上线顺序中保证兼容。

## 验证

覆盖文本/工具/文本的断线、运行中与完成后重连、原子快照与后续事件、多个会话隔离、截断、长文本和 Unicode、工具结果限额、新旧版本协商、重复连接以及原有待处理事项。验证真实 WhaleTerm 数据流和 iOS 真机长任务，确认输出顺序与 PC 一致；确认目前内存范围不提供全量历史或跨服务重启恢复。
