# 移动端按工作目录分组的会话列表设计

- 日期：2026-09-23
- 状态：用户已确认并反馈本阶段验证通过；Harmony DevEco 工程构建/真机仍待补
- 关联：D66/D67/D72、`docs/specs/2026-09-22-mobile-multi-session-runtime-design.md`

## 1. 目标与范围

React Web/Capacitor 与 HarmonyOS NEXT 的已配对会话列表按 Claude 实际工作目录 `cwd` 分组，覆盖 Standalone CLI 和 WhaleTerm Remote。用户能靠稳定标题、最近内容、状态、时间和刚查看标记辨认会话。React 列表使用已有依赖 antd-mobile 的 `List`；Harmony 使用等价 ArkUI 列表，不引入 React 运行时。

列表仍只展示本机已有配对记录，不枚举宿主的全部 Claude 会话；不保存完整 Claude 历史、不自动恢复未曾配对的会话，也不改变 WhaleTerm 无移动端新建入口的边界。

## 2. 页面信息层级

```text
项目目录名                  组内最近活动时间
完整 cwd（次要文字，可复制）
  会话标题                  进行中 / 等待处理 / 已结束
  最近内容摘要              未读
  最近活动时间 · 来源 · ID 摘要
  刚刚查看（仅刚退出的会话）
```

- 组标题取路径末段，保留完整目录作为副标题；路径相同的会话归为一组。路径缺失的旧宿主/旧配对进入“工作目录未知”组，保留地址摘要帮助辨认。相同路径可能存在于不同电脑，本阶段的组仅表示收到的 `cwd` 字符串相同，不声称是同一台机器；稳定机器身份和真正的机器分组另行设计。
- 卡片主标题优先用用户设置的本地名称；无本地名称时，用宿主观察到的首条非空用户输入首行规范化并截短，首次生成后保持不变。无可用输入时使用“新会话 · 创建时间”；缺少创建时间时用 ID 摘要回退。重新配对同一 `sessionId` 不覆盖本地名称。
- 最近内容摘要只取客户端已经收到、可展示的最新用户输入或 Claude 文本；内容缺失时显示状态说明，不读取本地 JSONL 或完整历史。会话标题和预览为纯文本，限制长度，不渲染 Markdown/HTML。
- 状态优先级为待处理、运行中、失败/已结束、空闲；连接异常、需重新配对和未读作为独立标记，不用连接成功时间冒充活动时间。
- 整行点击进入详情；重命名和删除收进该行的操作区域，避免每行三个按钮挤占标题与预览。原有“新增配对”入口继续保留。
- L3 列表紧凑化验收调整（用户已确认）：React/Capacitor 每行只保留单行标题、单行最近内容预览和关键状态/活动时间/未读提示；隐藏常驻 ID、地址、来源与“进入”按钮，整行仍进入详情；重命名和删除收进“更多”菜单。项目组仍提供完整目录供辨认。使用 antd-mobile `List` 及独立 CSS 控制行距、截断和高亮，不改变分组、排序及三端共用契约。

## 3. 分组、排序与定位

1. `lastActivityAt` 代表用户输入开始、Turn 完成、待处理事项出现或 Session 终态等有意义的状态变化，由宿主记录；`text_delta`、WebSocket 重连、进入详情和列表渲染均不改变它。无活动时间时使用会话创建时间；都未知时保持本地配对顺序。
2. 组按其会话的最大排序时间从近到远，组内按会话排序时间从近到远；同时间按本地记录顺序稳定排序。“工作目录未知”也按活动时间参与排序，不强行固定到底部。
3. 列表打开时冻结分组与行的相对顺序；状态、时间和未读标记继续实时更新。下次进入列表或用户主动刷新时重新排序。由详情返回时恢复滚动位置，并用“刚刚查看”标记及轻量高亮定位刚退出的会话；定位不改变真实活动时间。
4. 分组键使用宿主给出的非空绝对工作目录的原样值；跨平台只做显示用末段提取，不在手机端推断符号链接、大小写或不同机器的路径等价性。

## 4. 元数据来源与建议的共用契约

- Standalone CLI 使用 Runtime Manager 启动时固定的绝对 `cwd`，同进程新建会话沿用此目录。新建 Runtime 时记录创建时间；`--resume` 无可靠原始创建时间时标记未知，不把恢复时间冒充创建时间。首条用户输入和活动时间在 Session Controller 的串行事件边界捕获。
- WhaleTerm Remote Host 从已解析 Session 的 `ProjectPath` 取得目录，从 `SessionMetadata.CreatedAt` 取得可用的创建时间；首条输入与后续活动在该 Session Host 的事件边界捕获。若 Remote 开启前的首条输入没有现成可信标题，不扫描 JSONL 猜测，只在当前 Remote 生命周期第一次观察到用户输入后生成标题；更早历史仍以手动重命名或回退标题辨认。
- 建议让新服务同时支持 wire protocol v2/v3：v2 的 Snapshot/Event 保持原样；v3 的已授权 Session Snapshot 增加可选 `projectCwd`、`sessionTitle`、`createdAt`、`lastActivityAt`，有意义活动的事件增加可选 `lastActivityAt`，首次确定自动标题的 `turn_started` 增加可选 `sessionTitle`。时间统一用 RFC3339 UTC；未知字段省略。`text_delta` 不更新时间。项目目录只在认证及订阅成功后的 Snapshot 出现，绝不进入二维码、错误或未订阅响应。标题只保存有界首行摘要，不复制完整输入。
- 连接从 `hello` 的 envelope 版本选择 v2 或 v3，之后该连接的入站和出站保持同一版本。旧客户端连接新服务继续走 v2；新客户端先尝试 v3，遇到旧服务的 `unsupported_version` 后用同一已配对 `sessionId`/Token 重连 v2，并展示“工作目录未知”等回退。配对负载仍为版本 1，旧二维码继续可用。当前旧 Transport 会在未知消息后关闭连接，故不能以 v2 上的试探性新消息替代版本协商。
- 公共 `remote.Server` 仍只服务一个 Session；CLI Manager 和 WhaleTerm Host 为自身 Session 注入只读展示信息。v2 序列化必须排除新字段，v3 只能发送该已授权 Session 的信息；终态 Snapshot 保留最后标题、目录和活动时间。兼容性矩阵必须覆盖旧客户端↔新服务、新客户端↔旧服务、新客户端↔新服务。
- 三端共用契约只包含 WebSocket/JSON、可选字符串与时间戳，不依赖 DOM、Zustand、Capacitor 或 ArkUI。React/Capacitor 与 Harmony 必须使用同一组 v2/v3 协商、缺字段、跨 Session 拒绝、终态和标题稳定性验收用例。最终字段与双版本验证结论在代码实施前固化到 `DECISIONS.md`。

## 5. 验收要点

1. CLI 的 A/B 与 WhaleTerm 的 C/D 分别出现在真实 `cwd` 组中；不同端口但相同目录可归组，目录缺失的旧会话仍可访问。
2. 自动标题取首条已观察用户输入首行并保持稳定；手动标题优先；已存在会话无历史标题时按回退规则显示。
3. 重连不改变顺序；流式增量不使列表跳动；新活动在下次进入列表后改变排序；刚退出的会话能直接定位。
4. 进行中、等待处理、已结束、失败、断线、需重新配对和未读均可辨认；预览只使用已收到内容。
5. 旧客户端可继续连接新服务；新客户端连接旧服务回退 v2 后仍能收发基本消息；目录与标题不得越权发送给其他 Session；凭证和完整正文不进入新增展示字段。
