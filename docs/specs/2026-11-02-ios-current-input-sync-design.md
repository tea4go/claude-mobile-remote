# 配对时恢复当前提问：兼容方案（待用户检查）

## 问题与范围

手机在 PC 运行途中配对时，现有快照只含当前 Turn 的 Claude 输出，不含触发它的用户提问；历史不回放。用户需要看到当前提问。只恢复当前 Turn 的可展示输入，不扩展为完整历史，不改变 Host/Client/FIFO 所有权，不传 Pair Token 或本机临时附件路径。

## 方案

- 增加协议 v7：Turn 快照增加可选 `inputText` 字符串，表示当前 Turn 的用户可见提问。仅在有可靠展示正文时发送；无正文时省略，不伪造内容。文本按现有输入上限做字节与 UTF-8 校验。附件仅采用宿主已有的安全展示文本，不把生成的缓存路径或图片数据填入此字段。
- v2–v6 的快照必须剥离该字段，旧端严格解析行为和现有 `turn.message`（Claude 输出）不变。v7 客户端连接旧服务时应按已有协商降级至服务端版本；旧端连接新服务保持原有行为。认证和授权不变。
- Standalone Controller 持有当前输入，可复用现有 `DisplayInputText`；WhaleTerm 的活动 Turn 应复用现有用户可见输入来源，并在快照时按当前 requestId 精确匹配；若不能确定安全展示文本则省略。事件流按 Turn 身份保存和清理该字段，不能将上一轮内容带入下一轮。
- React/Capacitor 和 Harmony ArkTS 都在 v7 解析可选字段，并以 `sessionId + requestId` 与已有消息去重，先展示提问再展示回复；不重复当前进程已见的输入。缺字段或降级维持现有表现。不得把正文写入诊断日志；遵循现有消息缓存边界。
- 评估 JSON 编码后输入和回复合计的最大字节数，调整有界出站预算并测试控制字符最坏转义，防止大合法快照导致断线；维持慢客户端隔离与有界内存。

## 验证与兼容

三端均可使用基本字符串实现，无平台专属字段；Harmony 严格键白名单、状态归并及 v7→v6 降级必须同步更新。自动测试覆盖 v7 快照、v2–v6 剥离、旧服务降级、输入/回复同时存在、重连去重、Turn 切换和隔离、长文本及不可安全展示的附件。WhaleTerm 覆盖 PC 正在运行时配对，Standalone 覆盖运行中订阅；用户在 iOS 真机及 PC 复验。正式版本发布和 Harmony 真机验证另记，不能用编译替代。
