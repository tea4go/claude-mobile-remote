# iOS 图片与会话导航修复设计（用户已确认）

## 范围与现状

手机图片可能很大；当前仅 HEIC/HEIF 或超过 4 MiB 的图片会转换为最长边 2048 的 JPEG。用户反馈两张图片后 SDK 报 1 MiB JSON 解码上限，随后手机发送无法到达，而 PC 仍可继续。SDK v0.1.4 的 CLI 输出解析器默认上限确为 1 MiB，支持配置；尚未确认触发超限的具体输出、WhaleTerm 使用的实际配置及后续发送失败原因。

## 处理方案

- iOS 所有图片选择入口在上传前默认处理：对需缩小的照片控制尺寸与质量；小图保留原始文件，避免不必要的有损转换。截图应优先保持文字可读，透明图和动图不得静默破坏透明度或动画。转换失败保留草稿并提示，非图片文件保持原样。具体阈值在测试中确定，现行附件数量和服务端大小限制不变。
- 压缩只能减少输入负载，不保证 Claude 输出不会超过 SDK 解析上限。先复现并定位消息方向、宿主实际配置与出错后的状态；依据实际数据配置合理的有界解析上限，并验证超限或错误后不会错误显示为可正常发送。WhaleTerm 拥有自身 SDK Client，本仓库 Standalone 的设置不会自动改变其配置；不得擅自修改仓库外宿主。
- 会话顶部/底部导航改为紧凑的图标按钮，提供无障碍名称和足够触摸区域；状态行保留足够空间，检查窄屏与深浅色。按钮始终可用，避免遮挡正文与输入。
- 不改变三端协议或附件限额；先完成 iOS 测试及用户真机验收，再同步 Android 和 Harmony。

首版实现将超过 512 KiB 的 JPEG 限制最长边 2048 并以质量 0.85 重编码，若结果更大且原图未超限则保留原图；HEIC/HEIF 转换为 JPEG。PNG、GIF、WebP 原样保留，超过原有附件限制时仍需先处理；原始待转换照片超过 20 MiB 仍提示用户缩小。上述压缩不承诺输出一定低于 1 MiB。

## 验证

覆盖不同尺寸照片、截图、透明图/动图、失败与普通文件；验证两个图片同时发送、后续消息、解析器配置和出错状态；验证导航点击与窄屏布局。构建 iOS 并记录真实 WhaleTerm 与 iPhone 测试是否完成。原问题 3 单独继续排查，原问题 6 低优先级。
