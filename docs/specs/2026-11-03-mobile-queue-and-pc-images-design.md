# 手机队列同步与 PC 图片同步设计草案

状态：用户已确认（D110）；优先实施 PC 图片同步，双向队列后置。

2026-11-03 图片实现：v8 `turn_started` 可带经过格式、大小和数量校验的 `images` 与 `imagesOmitted`，仅限 PC 输入；旧版本剥离。每连接复用有界大消息槽位，槽位被占用或命令结果先于事件时退化为有数量的提示，普通消息仍受原预算限制。React 与 Harmony 按 requestId 接入附件模型，快照先于开始事件时合并图片；不写入图片缓存。当前仅向已订阅连接推送轮次开始时的图片，断线期间或开始事件之前完成的输入不能从快照恢复图片；引导输入的图片另待处理。正式 WhaleTerm 依赖尚未包含 v8，源码联调使用临时 modfile。

## 目标和现状

手机会话详情输入区提供队列入口，展示当前会话的真实队列，支持取消和引导；PC 和手机的入队、取消、引导及出队均反映到两端，重连恢复。PC 发送图片应在手机相应提问中显示。第 3、5 项用户复测已通过，不作为现存故障重复处理。

WhaleTerm Manager 已持有 FIFO、取消和 `SteerClaudeTurn`；手机已有队列快照展示及取消。WhaleTerm Remote Host 的快照已从宿主队列生成 `queuedRequests`，但变化未完整广播；公共协议没有远程引导命令。PC 的 `onturnstart` Remote 映射只发送文本，未传图片；原始输入图片路径及数据形式需继续核对，不能发送本机路径或任意读取文件。

## 契约建议

采用向后兼容的协议 v8。新端应能与 v2–v7 服务协商回退；服务对旧连接不发送新事件或字段。旧端继续使用现有快照和功能，不显示新能力。命令与事件严格按 sessionId、requestId 校验，未知能力禁用入口，不能断开旧连接。v8 引导能力由宿主显式声明；Standalone 未实现时不展示引导，不能假称两种宿主均支持。

队列仍由唯一 Session Host 管理。增加带完整队列视图的有序队列变更事件；每次真实入队、取消、引导成功、出队和清空均从权威状态发布，列表顺序与 `queueDepth` 一致。订阅快照与事件的 seq 边界必须避免连接或重连时遗漏及倒退；并发时使用现有宿主锁和事件发布顺序，失败操作不虚报成功。手机使用 requestId 合并，不采用另一套本地队列作为权威。Remote 引导命令调用 WhaleTerm 现有 `SteerClaudeTurn`，目标已出队或停止时返回明确失败并刷新队列；PC 的取消及引导成功后同样产生队列更新。手机仅在连接、能力及会话状态允许时开放操作；入口仍可显示空队列。

PC 图片复用现有附件显示模型，新增版本化的下行展示字段或专用事件，将用户实际提交的图片与对应 requestId 关联；只允许已验证格式和字节数据，不传执行缓存路径、凭证或任意 URL。优先复用宿主已接收的图片数据，进一步确认 PC 原始输入格式及其生命周期后确定提取方式。遵循现有单文件、总大小与类型限制；超限或无法安全获取时以明确占位提示降级，不中断文本或连接。不能将 base64 图片写入日志、持久化会话缓存或 Git。输入流、引导输入、纯图片、断线与去重均需覆盖。现有出站事件大小和 outbox 限额小于附件上行预算，设计实现必须明确有界传输和慢连接处理，不能仅放大限制而导致其他客户端断线或无界内存。

## 三端及验证

- Go 公共协议和 transport：v8 能力、命令、事件、限额、序列及旧版本过滤；WhaleTerm 接入其现有 Manager。Standalone 保持能力真实声明，并为其队列变化提供对应发布或明确降级。
- React/Capacitor（iOS、Android）：更新编解码与降级，输入区接入现有队列组件；显示 PC 图片，保留既有手机附件体验。
- HarmonyOS NEXT：核对并更新严格解码、版本降级和状态模型，使其能安全接收 v8；具体入口能力按同一契约实现或显式降级，不能因未知字段断连。
- 验证：旧版 v2–v7 连新服务、新端连旧服务；两端交替入队/取消/引导、并发竞争和断线恢复；PC 含文本图片、纯图片、队列引导图片、多个附件与超限降级；不同会话隔离、慢连接及发送失败。自动化通过后仍需 PC 与手机真实操作验收。
