# 手机队列同步与 PC 图片同步设计草案

状态：用户已确认（D110）；2026-11-09 确认恢复实施 WhaleTerm 双向队列，入口及统一队列补充见下文。

2026-11-03 图片实现：v8 `turn_started` 可带经过格式、大小和数量校验的 `images` 与 `imagesOmitted`，仅限 PC 输入；旧版本剥离。每连接复用有界大消息槽位，槽位被占用或命令结果先于事件时退化为有数量的提示，普通消息仍受原预算限制。React 与 Harmony 按 requestId 接入附件模型，快照先于开始事件时合并图片；不写入图片缓存。当前仅向已订阅连接推送轮次开始时的图片，断线期间或开始事件之前完成的输入不能从快照恢复图片；引导输入的图片另待处理。正式 WhaleTerm 依赖尚未包含 v8，源码联调使用临时 modfile。

## 目标和现状

手机会话详情输入区提供队列入口，展示当前会话的真实队列，支持取消和引导；PC 和手机的入队、取消、引导及出队均反映到两端，重连恢复。PC 发送图片应在手机相应提问中显示。第 3、5 项用户复测已通过，不作为现存故障重复处理。

原始排查时 WhaleTerm Manager 已持有 FIFO 和 `SteerClaudeTurn`，手机已有快照及取消。后续 v8 已提供 queue_changed、steer_queued 和 PublishQueue，但 WhaleTerm 接线尚未完成。2026-11-09 进一步核实 PC 可见待发队列先存 Vue 本地，执行/引导时才提交 Manager，因此需先统一入队，不能仅广播 Manager 的既有队列便宣称双向同步。

## 契约建议

采用向后兼容的协议 v8。新端应能与 v2–v7 服务协商回退；服务对旧连接不发送新事件或字段。旧端继续使用现有快照和功能，不显示新能力。命令与事件严格按 sessionId、requestId 校验，未知能力禁用入口，不能断开旧连接。v8 引导能力由宿主显式声明；Standalone 未实现时不展示引导，不能假称两种宿主均支持。

队列仍由唯一 Session Host 管理。增加带完整队列视图的有序队列变更事件；每次真实入队、取消、引导成功、出队和清空均从权威状态发布，列表顺序与 `queueDepth` 一致。订阅快照与事件的 seq 边界必须避免连接或重连时遗漏及倒退；并发时使用现有宿主锁和事件发布顺序，失败操作不虚报成功。手机使用 requestId 合并，不采用另一套本地队列作为权威。Remote 引导命令调用 WhaleTerm 现有 `SteerClaudeTurn`，目标已出队或停止时返回明确失败并刷新队列；PC 的取消及引导成功后同样产生队列更新。手机仅在连接、能力及会话状态允许时开放操作；入口仍可显示空队列。

PC 图片复用现有附件显示模型，新增版本化的下行展示字段或专用事件，将用户实际提交的图片与对应 requestId 关联；只允许已验证格式和字节数据，不传执行缓存路径、凭证或任意 URL。优先复用宿主已接收的图片数据，进一步确认 PC 原始输入格式及其生命周期后确定提取方式。遵循现有单文件、总大小与类型限制；超限或无法安全获取时以明确占位提示降级，不中断文本或连接。不能将 base64 图片写入日志、持久化会话缓存或 Git。输入流、引导输入、纯图片、断线与去重均需覆盖。现有出站事件大小和 outbox 限额小于附件上行预算，设计实现必须明确有界传输和慢连接处理，不能仅放大限制而导致其他客户端断线或无界内存。

## 三端及验证

- Go 公共协议和 transport：v8 能力、命令、事件、限额、序列及旧版本过滤；WhaleTerm 接入其现有 Manager。Standalone 保持能力真实声明，并为其队列变化提供对应发布或明确降级。
- React/Capacitor（iOS、Android）：更新编解码与降级，输入区接入现有队列组件；显示 PC 图片，保留既有手机附件体验。
- HarmonyOS NEXT：核对并更新严格解码、版本降级和状态模型，使其能安全接收 v8；具体入口能力按同一契约实现或显式降级，不能因未知字段断连。
- 验证：旧版 v2–v7 连新服务、新端连旧服务；两端交替入队/取消/引导、并发竞争和断线恢复；PC 含文本图片、纯图片、队列引导图片、多个附件与超限降级；不同会话隔离、慢连接及发送失败。自动化通过后仍需 PC 与手机真实操作验收。

## 待核对

确认 PC 输入图片在宿主的真实数据形态、大小和生命周期；确定有界出站图片传输方式及完整快照与事件的原子边界。完成设计审查和用户确认后，将确定的三端兼容决策记入 DECISIONS，再实施协议修改。

## 2026-11-09 已确认队列实施补充

- 本轮仅开放 WhaleTerm：PC 待发输入及时提交既有 Manager FIFO，Vue 只保留展示和编辑所需本地元数据，不再等待前一轮结束后才提交。手机输入复用相同 FIFO，无第二个 Client 或执行器。
- 宿主普通等待项最多 32 条，与现有公共控制器的有界 FIFO 目标一致，预览最多 200 字符，避免队列事件超过普通传输预算；PC 原有本机 10 条提示保留，最终以宿主受理为准。明确拒收保留 PC 原草稿供取回，结果未知不自动重发。
- 移动入口放在输入卡左下方 permission 右侧，显示数量，仅在支持的宿主且有排队项时出现，替代上文空队列入口及输入卡上方入口安排。打开有界底部抽屉，展示顺序、来源和截断预览，支持取消和可用的引导；队列清空后收起。断线可查看上次状态但禁止操作，重连以快照校正；失败 Toast 提示，不自动重发。
- PC 编辑仍取回草稿：必须先经宿主确认目标仍排队并移除，再恢复本地原草稿；手机来源项没有 PC 原始附件草稿时只提供取消/引导。排序在宿主锁内按目标 ID 移动，保留并发新增项，目标已出队则失败，不把旧列表覆盖整个队列。
- 每次入队、出队、取消、排序、引导成功和删除清理均生成权威队列视图。Manager 锁内确定变更顺序，订阅先安装快照后接收后续有序变更；不得用锁外异步读取的旧队列覆盖新状态。PC 通过 Wails 队列事件和当前快照同步；手机复用 v8 queue_changed。PC 的完整附件草稿不进入共用协议。
- 复用现有 v8 steer_queued / canSteerQueue 能力门控，WhaleTerm Controller 接入已有引导函数；Standalone 不声明该能力，移动入口保持隐藏。v2–v7 保持现有降级，Harmony 已有 v8 解析仍可接收队列，独立入口本轮不开放。无需新增跨端消息类型或平台字段。
- 验收覆盖两端交替入队、PC 编辑/排序、两端取消和引导、自然出队、断线重连、目标被抢先执行、附件草稿及会话隔离。补充 Go 和前端用例；按用户要求不运行 npm lint/build/test，不复制旧 Web 资源。

正式依赖核对：WhaleTerm 当前 v0.0.9 已包含所需 v8 队列事件、引导命令和 PublishQueue；上文关于正式依赖尚缺 v8 的描述为 2026-11-03 当时的历史状态。


### 2026-11-09 移动端交互调整

队列保持底部抽屉，队列项纵向展示顺序、来源和内容预览；点击后通过 ActionSheet 提供引导及取消排队。断线时只读，队列清空时收起。首页电脑筛选使用 Picker 滚轮，确认后应用选择，取消不改变筛选；沿用原有偏好持久化、单电脑默认和删除回退。React 界面供 iOS/Android 共用，Harmony 后续独立实现等价交互；不修改共享协议。
