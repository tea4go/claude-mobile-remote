# C2-C 原生配对逻辑准备设计

- 日期：2026-09-24
- 状态：用户确认本轮范围；原生适配器与真机门禁后续实施
- 依据：C2 设计 §2.3–2.4、D41、D54、D66

## 目标与边界

在 React/Capacitor 共用的 TypeScript 代码中建立不依赖设备 API 的配对存取与生命周期逻辑。系统安全存储、普通应用私有存储、扫码相机和 App 状态事件均通过注入端口接入；本轮不选择或安装原生插件，也不声称已经安全保存凭证。

浏览器继续只保留 Fragment 与内存配对。新的原生协调器不由 Web App 默认构造，也不使用 Web Storage。Pair Token 与完整 Pairing 负载只能传给安全存储端口；普通元数据端口只接收 `sessionId`、本地名称和上次连接时间。扫描结果调用现有 `parsePairingInput` 校验，不重新定义配对 JSON。通信协议和三端共用状态不变，Harmony 后续可实现等价端口与行为。

## 数据与操作

- `SecurePairingPort`：按 `sessionId` 读取、写入、删除完整 Pairing；正式原生实现必须由 Keychain/Keystore 支持的安全方案承载。
- `PairingMetadataPort`：列出、写入、删除无凭证的本地元数据；可由原生应用私有存储承载。
- `NativeScanPort`：相机插件以后只需返回扫码文本；取消返回空值。`scanAndSave` 复用同一解析和存取路径。
- `NativeAppStatePort`：以后提供前台事件与取消监听函数；观察器在每次事件到来时读取最新配对并产出刷新计划。
- `restore(now)`：按元数据顺序读取安全记录，用现有 Pairing 校验验证版本、URL、会话 ID、有效期；有效记录返回连接候选，缺失、损坏、错绑和过期记录只返回需重新配对的元数据。过期安全记录尝试删除；删除失败也不得把过期凭证交给连接层。
- `saveScanned(input, now)`：先解析扫描文本，再更新元数据与安全记录。同一 `sessionId` 保留用户本地名称；失败不向 UI 回传原始凭证。元数据先落地，安全写入失败时最多留下需重新配对的元数据。
- `remove(sessionId)`：先删除安全记录，再删除元数据；安全删除失败时保留元数据，调用方不能误报删除完成。
- `rename`：只更新元数据，不访问安全记录。

本轮协调器返回恢复结果，不自动写入 `AppStore` 或启动 WebSocket。原生适配器接线时按有效候选调用既有 `upsertPairing` 与 `SessionRuntimeManager.ensureConnected`；需重新配对的记录另行在原生列表中呈现。这样不会把未实现的存储能力伪装成已经生效的功能。

## 前台恢复

纯函数根据当前配对、连接状态和时间产生计划：过期配对进入需重新配对；有效配对都需要刷新连接状态。已断开的连接保持手动重连边界，前台事件本身不建立新连接。后台事件不持久化消息正文，也不改变 WebSocket 协议。原生 App 状态监听在后续适配器阶段接入。

## 无设备验收

注入内存测试端口，覆盖多 Session 恢复、同 ID 凭证替换、过期/错绑/损坏凭证、存储故障、删除顺序、扫描输入和前台计划。运行 Vitest、lint、build；记录未接线的原生能力与真机门禁。测试端口只作测试夹具，不作为产品的凭证存储实现。
