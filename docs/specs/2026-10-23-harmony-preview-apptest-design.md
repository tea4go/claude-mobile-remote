# Harmony Mac 界面预览与 AppTest 测试发布

- 日期：2026-10-23
- 状态：用户已检查通过；预览及未签名Release打包已实施，发布签名和后台分发待材料。
- 依据：用户确认 Mac 轻量界面预览与 AppTest 邀请测试，沿用 SDK 6.1.1(24)。

## 1. 当前基础与目标

现有外接盘 Command Line Tools 可编译未签名 Debug HAP，包含 Previewer 二进制和运行库，但独立预览尚未验证。当前只有已核验的 Debug 证书和本机密钥库，没有发布证书、发布 Profile 和已验证的 AppTest 上传产物。

目标一是在 Mac 上从终端查看并操作本工程 ArkUI 界面，避免先安装完整模拟器。目标二是生成供 AppTest 邀请测试使用的软件包。用户所称“调试版本”按测试用途理解，构建模式、证书类型和渠道包格式分别核实，不将其等同于 Debug 签名。

## 2. 界面预览

1. 先检查配套 Hvigor 的预览任务和 Previewer 参数、运行依赖，使用官方工具的实际接口；不得将 HAP 当作 macOS 可执行程序或直接预览输入。
2. 优先构建和运行最小 ArkUI 页面，再接入现有 AppShell。独立预览若需要 IDE 提供的宿主或通信服务，记录具体阻塞并向用户报告，不自动安装大型 IDE、模拟器或升级 SDK。
3. 实施后提供 `scripts/macos/3_harmony_preview.sh`，复用稳定工具链链接与进程级环境；产物与日志写入 Git 忽略目录。提供帮助和明确的错误结果；启动失败不报告成功。
4. 用现有页面组件展示虚构会话、消息、工具结果及审批数据，支持进入详情、返回、设置与抽屉交互。预览入口显式隔离于正常应用入口，生产打包不得默认启用预览数据。
5. 扫码、HUKS、文件持久化、语音和通知在预览路径中使用受限适配，不读取真实配对、不连接真实 PC、不生成真实审批或消息操作；复用现有平台中立模型，不改变协议。
6. 改码后的重新构建、刷新方式以实际工具能力为准；不承诺热更新、断点调试或与设备完全一致的布局。

## 3. AppTest 发布构建

1. 先核实当前 HarmonyOS AppTest 邀请测试的官方流程、包格式与签名要求，避免混用旧版开放式测试和其他分发渠道规则。后台实际入口与账号资格需人工登录确认。
2. 保持包名 `com.tea4go.claudemobileremote`，由用户在后台确认归属和应用标识。若已有应用标识不一致，停止签名并报告，不擅自更换包名。
3. 发布私钥、CSR、发布证书、Profile、密码及本地配置保存在仓库外私有目录，独立于现有 Debug 材料。已有 Debug 密钥和证书不覆盖、不自动废除。
4. 本机可准备发布 CSR；由用户登录华为后台申请匹配的发布证书和渠道要求的 Profile。收到文件后验证公钥、有效期、包名及 Profile 类型等可验证信息。尚无材料时构建入口明确报告缺失，不回退未签名包冒充发布成功。
5. 新增独立 AppTest 构建入口，执行官方要求的构建、签名和发布打包流程。上传产物格式在核实后固定；预计采用应用级 APP 包，但以官方要求与实际后台校验为准。
6. 密码不写入受跟踪配置、命令回显和构建日志。采用工具支持的密码输入机制；必要的本地临时配置权限0600并在正常/异常退出时清理。日志只记录脱敏结果和非敏感产物摘要。
7. 验证 ZIP 结构、包名、版本、API、签名与 Profile 一致性，输出准确路径与 SHA-256。构建检查通过不等于后台接收成功或设备安装通过。
8. 上传与创建邀请测试任务按后台实际可用能力执行；账号登录、协议确认及当前不可自动化的步骤由用户完成。发布、邀请操作前展示具体应用、版本和范围，不自动向同事发送消息。

## 4. 边界与验收

- 不修改 iOS、Android、PC 服务端、通信协议、Session 所有权和输入队列。
- 不新增模拟器、不升级 SDK、不自动提交或推送。
- 预览门禁：实际启动并观察到 ArkUI 页面，检查列表、详情、设置、抽屉及基本输入；确认无真实配对或 PC 写操作。截图和结果不含凭证。
- 构建门禁：脚本语法与帮助检查，原有 Harmony 回归，实际构建与产物核验；发布材料缺失则仅记录准备完成，不能宣称发布成功。
- 分发门禁：后台接受指定版本并创建测试任务，同事实际通过 AppTest 安装。设备系统需满足当前最低 API24；预览结果不能替代扫码、HUKS、语音、通知等设备验收。
