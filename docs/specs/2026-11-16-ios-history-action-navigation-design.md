# iOS 图片历史、待办与导航设计草案

状态：待用户检查；实现与验收先 iOS，之后再同步 Android 和 Harmony。

## 图片历史

移动端现有离线缓存明确移除附件字节，仅保存文件名；PC 上传附件通过临时文件路径交给 Claude，文件清理周期为 7 天。当前路径提示是执行输入，不等于可长期恢复的图片历史。WhaleTerm 刷新后的历史数据来源和可读取路径尚未核实，不能保证已过期或已清理的图片能恢复。

用户要求手机发图与 PC 发图采用一致的会话消息表示。已核对允许参考的 WhaleTerm SDK 代码：PC 将文本与 base64 图片块组成结构化 user message，通过 SDK `QueryStream` 写入 CLI，会话 transcript 因此保有图片块。手机目前通过公共服务把图片落临时文件，并将文件路径拼为文本；展示用的 `InputDisplay` 是旁路数据。差异来自此前 D81 选择复用文本队列及文件读取，并非图片本身必须不同。

优先方案：在唯一 Host 和 FIFO 中保留经过验证的结构化图片输入，WhaleTerm 使用与 PC 相同的图片块和 QueryStream 路径；文本与非图片附件混合时保留可用行为，明确支持格式及不支持格式的反馈，不静默丢弃。Standalone 的 SDK 输入能力、队列、取消和引导都需单独核实，不能以只改展示替代。实现需验证异步 QueryStream 生命周期、图片大小上限和现有 1 MiB 解析错误，不能假设统一输入即可修复该错误。旧版本已有路径消息仍按可得数据降级，不能承诺恢复已清理文件。

具体接线：上传时继续生成原有完整路径文本供旧宿主和 Standalone 使用；额外向进程内宿主传递服务端生成的、按附件顺序排列的暂存路径，字段不序列化或进入网络协议。WhaleTerm 校验受限格式和图片字节，将有效图片构造为与 PC 相同的原生图片块，普通文件使用对应可信路径；不支持或伪装的图片作为普通附件沿用文件读取。所有内容仍通过同一队列和 Client。该接线不改变线协议、配对、移动端状态或三端验收契约；React/Capacitor 与 ArkTS 继续使用既有附件命令。

手机重启后的历史展示仍需另行处理：当前缓存不保存图片，已有快照不提供完整历史。先核实 PC 历史能否在已授权 Session 范围内安全提供所需图片、以及现有缓存是否需要受限缩略图；不能假设结构化输入会自动使手机恢复历史，也不能以本地缩略图替代 PC 端历史一致性。若需缓存，需规定隐私、大小、淘汰与清除规则。

### 手机图片恢复（用户已确认方向，D127）

本次范围仅覆盖今后移动端发送的图片，旧消息和 PC 发起的图片不追溯。

用户明确图片资源不存储在手机，要求尽量统一从 PC 获取；下方“本地图片预览”备选方案已撤回，不实施。拟采用最小按需获取：手机持久化消息中的不透明图片标识与名称，不持久化图片内容；恢复时通过现有已认证 Session 连接请求 PC 返回对应图片，图片仅在当前进程内展示。PC 不可达、图片已清理或旧记录没有标识时保留附件名并提示不可用；不扫描、猜测或按附件名匹配历史图片。

PC 端以 Session 隔离的索引映射不透明标识到既有上传暂存的图片数据，不能接受客户端文件路径；复用现有限额与清理机制并明确资源保留期限，单次按需返回有界数据，不扩展完整历史查询。沿用暂存目录 7 天及容量清理规则，清理后显示附件名；须验证 PC 重启、队列取消和重复图片；不得假定 WhaleTerm 的 requestId 与 CLI transcript 标识对应。已经保存为纯附件名的旧记录没有可靠标识，原则上不能自动恢复。

实现需要版本化协议、三端纯数据兼容和旧服务降级，核对结果记入已确认决策；iOS 先实现和真机验收，之后同步 Android/Harmony。需覆盖授权隔离、标识伪造、限额、PC 不可达、文件过期、重启、混合附件及不持久化图片内容的测试。

### 已撤回的手机本地图片预览备选

真机反馈已确认手机发送的图片在 WhaleTerm 展示及 PC 应用刷新后正常；移动端退出后只显示附件名。原生缓存按 D84 的既有实现主动丢弃图片字节，重连快照不提供完整历史，因此移动端需另行保存已收到的预览，不能依赖本次 PC 展示结果自动补回。

- iOS 先行：仅对消息中已收到的图片生成最长边不超过 512 像素的静态 JPEG 预览，单张编码后不超过 64 KiB；生成失败或超限时保留文件名和预览不可用提示，普通附件继续保留名称。预览仅供显示，不用于发送、执行或恢复模型上下文。
- 使用现有私有 Session 缓存和文件保护，不新增协议、历史查询或浏览器持久化；沿用每 Session 2 MiB、最多 200 条、总量 20 MiB 和 30 天规则，优先保留较新消息。清除离线缓存或移除配对时一并删除预览，异步生成和写入须服从现有串行队列，避免清除后复活。缩略图随缓存保存在设备上，可能包含图片内容；动画仅保存静态帧，透明图转 JPEG 时采用白底。
- 旧缓存只有附件名而无图片字节，无法从本地恢复旧图；不会补取应用关闭期间未收到的图片。缓存损坏、生成失败或被系统淘汰时明确降级，不影响文本和重新连接。
- iOS、Android 可使用现有 Web 图片解码和原生私有文件；Harmony 后续可使用平台图片解码和私有文件实现等价规则。无 wire、配对或共享状态模型变化；iOS 验收后再同步其他平台。
- 验证图片与普通附件混合、图片生成失败、容量淘汰、旧缓存、删除/清除与写入竞态及快照合并；iOS 构建后以真机发送图片、完全退出并重开验证。实现前需将该缓存策略作为对 D84 不保存图片字节的局部调整记录确认。

本方案改变 D81 的图片执行方式；具体宿主接口与契约、旧端降级和三端可实现性须核实后形成完整设计并记录确认决策，再实施。WhaleTerm 仓库修改须在允许访问和工作区权限内处理。

## 待办与导航

- 权限和提问面板保留右上角收起，收起仅改变显示并保留已输入内容；底部提供取消。权限取消当前 Turn，提问使用现有协议的提问取消语义；按钮遵守连接、在途门控，发送失败允许重试，收起不发送命令。
- 收起态提供紧凑、可辨认的待办入口，能重新打开；不遮挡输入和消息。
- 导航悬浮在消息区右下角、输入区上方，与状态行分开。实际滚动位置决定顶部和底部按钮显隐；内容变化、容器尺寸变化和滚动均更新，短内容两者均隐藏；保留无障碍名称与触摸区域，避免遮挡交互。
