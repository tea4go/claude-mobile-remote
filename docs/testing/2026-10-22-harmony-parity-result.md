## 本轮修复的具体问题

- Harmony v3 无法展示 v4 工具结果正文；补 v4/v3/v2 协商与版本门控。
- 附件经 PC 转换为临时路径后回显不同会误报协议异常；附件输入按已受理 requestId 归并。
- 大附件使用重复捕获正则会栈溢出；改为线性字符校验并保留字节限制。
- 重连会丢弃此前已见消息；恢复静态展示消息，由 snapshot 替换当前 requestId 的 Claude 内容。
- 主动断开/重新连接时未释放待发送状态；标记未知并保留草稿，不自动重发。
- 旧 socket 的异步 send 失败可能关闭新连接；增加连接代次校验。
- 移除会话时异步创建中的通知可能迟到；发布前后检查当前会话通知标识和开关。

## 提交前审查补充

用户随后明确要求仔细审查并提交。本轮审查发现并修复：

- 补齐遗漏的 D61 权限模式快照/事件/命令及界面选择器；原解码器会拒绝现有服务端携带 permissionMode 的快照。已对照 React 协议接口与 Go 发送实现，模式只按 PC 回传更新，不清除已有审批，缓存不恢复权限执行态。
- 第二个操作会覆盖尚未受理命令的本地关联；现在忙态直接拒绝，保留原命令与附件。协议序号异常时释放发送草稿锁定；主动断开通知界面解除会话管理忙态，结果未知不擅自重发。
- 通知发送串行排序；删除先使异步任务失效，即使系统撤回失败也不再发布迟到提醒；打开详情仅撤回通知，保留 seq 去重基线。
- 消息、Markdown、附件和会话列表的 ForEach 键纳入展示变化，修复普通对象更换后固定键复用旧内容的问题；依据 [ArkUI 官方 ForEach 规则](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/ui/rendering-control/arkts-rendering-control-foreach.md)。补齐 KeyboardAvoidMode 显式导入。
- 清缓存后连接状态变化不再把相同展示内容写回；后续收到新内容仍按既有缓存规则保存。重连保留 cancelled 状态。
- 单条损坏的配对元数据不阻断其他有效记录恢复；并发语音启动只保留最后一次；页面销毁/重建用代次隔离初始化回调。
- 终止会话确认绑定打开弹窗时的 Session，防止通知切换详情后误操作另一个 Session；列表排序补齐新增项之间的稳定比较。

## 用户真机验收清单（全部待验收）

1. **工程和安装**：在装有对应 SDK 的 DevEco 环境构建，修正任何实际 ArkTS/SDK 错误，安装启动。检查中文、键盘避让、返回手势、列表滚动恢复、抽屉内部滚动和小屏输入工具栏。
2. **配对与安全恢复**：扫描两个不同 Session，中文 PC 名称正确；拒绝/取消扫码可粘贴；杀进程重开恢复配对与已见消息。错误凭证/自然过期提示重扫；删除单 Session 或 PC 后重开不恢复已删除记录。
3. **会话闭环**：首轮前输入，PC/手机连续交替消息、流式文本/状态刷新、审批三决议、单选/多选/文本问答、队列取消、运行中停止；Turn 完成后继续输入。权限模式按 PC 返回值显示，切换失败保持原值、已有审批仍需显式处理。CLI 按能力新建/终止，其他 Session 不受影响；终止确认期间切换详情仍只操作原 Session。
4. **附件**：图片、拍照、文件三入口，追加/移除/预览；仅附件、文字组合均由 PC 真正受理并被 Claude 读取；超限/格式失败提示；断网、拒绝和超时保留草稿且不重发。验证 HEIC 转换。
5. **语音**：首次权限拒绝、授权、识别为可编辑草稿、手动发送、完成/取消、60 秒超时、系统中断及切后台清理；切换会话后无迟到文本串入。
6. **提醒**：默认关闭，开启权限；前台当前详情静默，其他 Session 的审批/问题/完成/失败/停止可提醒，文案无正文；点击已保存 Session 正确定位，杀进程后点击已有通知恢复；移除后不再定位或出现迟到提醒。
7. **缓存与 VPN**：离线重开只显示本机已收内容，运行/审批/队列不可恢复执行；清除缓存再重开不恢复旧缓存；多 Session 隔离。VPN 直连、退后台再回前台按 PC snapshot 校正。系统挂起期间的新事件不保证收到。
