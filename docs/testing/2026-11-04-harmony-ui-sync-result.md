# Harmony 新版移动端同步检查点（2026-11-04）

用户要求按 iOS 已验收功能独立实现 Harmony UI，重视性能；本记录是进行中检查点，并非 UI-5 人工验收通过。

- 已实现：ArkUI PC/目录/会话分组、折叠、筛选及本地偏好；目录创建和定向配对的 PC ID/cwd 校验、候选连接和安全保存门控；新版配对、设置、消息、问答选项、步骤抽屉、原生复制及语音停止状态；详情新建和队列入口隐藏。调试入口默认关闭，日志仍记录有界脱敏信息。既有系统通知范围未扩展。
- 性能措施：会话列表及消息使用 LazyForEach，分组一次遍历、排序用索引表，列表投影无变化保持引用；原生文件保持异步串行；工具结果索引按轮次隔离，输入预览做延迟解析。以上为实现和自动化证据，不代表触摸时延达标。
- 验证：Harmony 79 项测试及 20 个逻辑文件检查通过；官方 6.1.1/API24 Debug 未签名 HAP 构建及预览工程编译通过，HAP SHA-256 `c2ff36752d27694674ad6c8e1869ccfdcd86ee8d39d8c8d356799f4e75180d87`。`git diff --check` 通过；构建存在既有 ArkTS 弃用等警告。
- 限制：`hdc list targets` 无设备。预览服务报告画面就绪，但截图读取因自动审批额度限制未执行，未核实实际视觉；未测扫码、配对持久化竞态、创建结果和错误、系统弹层、键盘、安全区、相机、语音、长列表流式滚动或触摸时延。页面外观、动画和入口与 iOS 仍需逐项对照，不可视为已全部同步。未运行签名 Release，不上传、不提交。
- 下一步：恢复预览视觉检查后逐项完善列表卡片、图标、步骤样式、附件及问答体验；在设备或云测检查目录身份隔离、后台中断/存储失败、长列表与原 250ms 场景并保存实际结果。Harmony 设备可用前不能宣称性能门禁通过。
