# PC 图片同步验证记录（2026-11-03）

- WhaleTerm 在活动轮次中从 PC 的 base64 图片块提取数据，校验数量、大小和图片签名；纯图片轮次可生成有效事件。图片不包含 PC 路径。公共 v8 事件承载图片，v2–v7 过滤新增字段；不可安全传输的图片按数量提示。React 和 Harmony 根据 requestId 关联输入，图片不写入消息缓存。
- Go 全量 `go test -race ./...`、`go vet ./...` 和 `go build ./...` 通过（临时 GOCACHE、`GOFLAGS=-buildvcs=false`）。真实 WebSocket 测试覆盖约 2 MiB 图片及 v7/v8 同时连接，另有大消息槽占用和命令缓冲降级测试。
- React 全量 570 项、lint 和生产构建通过，lint 有既有脚本 warning、构建有既有 chunk 提示；快照抢先于事件时图片归并的定向回归通过。
- Harmony 71 项、17 文件逻辑检查与官方 API24 未签名 Debug HAP 编译通过；有既有平台弃用警告。快照抢先、v8 队列兼容及旧版拒绝图片字段有回归。
- WhaleTerm 使用 `/private/tmp/cmr-whaleterm-v7/go.mod` 临时引用本项目，图片提取、纯图片轮次及关联定向 race 和主程序构建通过；已有 macOS 弃用与链接警告。正式 go.mod 仍为 v0.0.8，尚未包含本次公共接口；未修改正式依赖或发布。
- 限制：仅实时事件包含图片，订阅前或断线期间的图片不能由快照重建；PC 引导输入图片未覆盖。图片超出限制、传输槽位占用或命令事件缓冲时显示未同步数量。未进行真实 PC/手机操作、原生安装、慢网络或真机/VPN 验收；双向队列另行实施。

人工验收：使用含新公共代码的 WhaleTerm 与新手机构建，检查 PC 文本加图片、纯图片、多图与过大图片提示；确认另一 Session 不出现该输入，以及手机发图和普通文本仍正常。
